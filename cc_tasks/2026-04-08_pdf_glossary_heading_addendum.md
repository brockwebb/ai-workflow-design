# Addendum: Glossary Heading Missing in PDF

**Date:** 2026-04-08
**Amends:** `cc_tasks/2026-04-08_pdf_backmatter_fixes.md`

---

## Problem

The glossary file (`book/glossary.md`) has no `# Glossary` heading. It starts with an HTML comment and the `{glossary}` directive. After `convert_glossary()` strips the directive wrapper, the output is just bare definition list entries with no heading. Pandoc sees no level-1 heading, so `typst_header.typ`'s `#show heading.where(level: 1)` pagebreak rule never fires. The glossary content flows directly into (or out of) the adjacent section without a page break.

The other back matter files (`index.md`, `bibliography.md`, `appendix-security.md`, `appendix-principles.md`) all have `# Heading` as their first content line.

## Fix

In `process_file()` in `build_pdf.py`, add a heading for the glossary:

```python
def process_file(filepath, filename):
    with open(filepath, "r") as f:
        text = f.read()

    text = strip_jupytext_frontmatter(text)
    text = process_directives(text)

    if filename == "cover.md":
        return None

    if filename == "intro.md":
        text = strip_cover_image_from_intro(text)
        text = strip_web_only_from_intro(text)

    # Glossary has no heading (auto-generated by Seldon) — add one for PDF
    if filename == "glossary.md":
        text = "# Glossary\n\n" + text

    text = number_figures(text, filename)
    return text
```

Do NOT modify `book/glossary.md` itself -- it's auto-generated by `seldon glossary generate`. The heading injection is PDF-pipeline-only.

## Also confirm: bibliography ordering

The bibliography being at the very end is correct and standard for books. Pandoc `--citeproc` appends references after the last content. With `bibliography.md` moved to be processed last, references appear under the Bibliography heading. This is the intended behavior.
